# 开题手记运行配置

在网站左下角打开「设置」。老师可以修改网站默认模型和推理强度，学生可以查看。缺省为 **GPT-6.1 Sol（轻度）**，对应 `gpt-6.1-sol` 和 `low`。网页保存会更新学生和老师的默认值。

默认配置来自 `proposal_app/runtime-config.json`。JSON 文件使用下面的字段。

| 分组 / 字段 | 用途 | 当前值 |
| --- | --- | --- |
| `student.model` | 学生辅导后台启动使用的模型 | `gpt-6.1-sol` |
| `student.reasoning_effort` | 学生后台准备回复的思考强度 | `low` |
| `student.prepare_timeout_seconds` | 学生后台 Codex 消息处理等待上限，秒 | `240` |
| `student.e_draft_timeout_retries` | E阶段首次生成固定稿超时后，关闭旧连接并在原会话自动续接的次数 | `1` |
| `teacher.model` | 老师辅助审阅后台启动使用的模型 | `gpt-6.1-sol` |
| `teacher.reasoning_effort` | 老师后台准备审阅的思考强度 | `low` |
| `teacher.prepare_timeout_seconds` | 老师后台 Codex 消息处理等待上限，秒 | `240` |

例如，将 `teacher.reasoning_effort` 改为 `high`，只影响老师后台审阅；学生保持原配置。更长的审阅需要更多等待时间时，可同时把老师的超时改为 `480`。

## 生效范围

通过插件打开 Codex 时，插件按当前连接账号与网站配置版本同步 Codex 的用户默认值。已打开的旧聊天以 Codex 里实际选择的模型为准。本机有优先级更高的配置时，应查看实际生效状态。以下后台等待和自动续接说明适用于旧的本机直启模式。

- 每次实际启动后台准备时重新读取，修改配置无需重启网站。首次安装这项代码更新需要重启一次服务。
- 新会话、连接中断后的恢复、教学规则更新触发的后台续接，都显式传入对应角色的模型和强度，优先于本机 Codex 默认设置。
- 已经运行中的准备使用启动时的配置快照，不会中途切换。
- 点击进入已准备好的旧会话只是打开 Codex，不会重新运行后台准备，也不会强制改写旧会话设置。进入 Codex 后的后续手动对话以 Codex 会话中的实际设置为准。
- 超时从后台消息处理循环开始计算，不包括此前目录注册与 Skill 安装；它也不是学生整场讨论的时限。
- E初稿自动续接每次仍使用同一配置快照和240秒消息处理上限，最多两次尝试。续接先读取实际保存结果，已有固定稿则复用，不重复创建；不代替本人确认、答辩或提交。仅在启动时为E且尚无固定稿时启用，不自动重试其他阶段、老师审阅、失败或中断。第二次仍超时则明确报错并保留原会话。

## 合法值

- `model`：填写当前 Codex 账号可用的模型标识，不含空格。应用不维护模型名称白名单。
- `reasoning_effort`：允许 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`、`ultra`。具体模型支持哪些强度由 Codex 决定；通过文件校验不代表模型必定支持该组合。
- `prepare_timeout_seconds`：30～3600 的整数。
- `student.e_draft_timeout_retries`：可选，整数0或1；0关闭自动续接，省略时为0。默认配置为1。

配置缺失、JSON 格式错误、拼错字段或类型不正确时，网站显示“启动配置错误”，不会悄悄改用其他默认值。修正后从网站重试。

## 其他参数放在哪里

| 参数 | 当前入口与处理方式 |
| --- | --- |
| 监听地址、端口、数据库 | 使用 `server.py --host / --port / --db`；数据库也支持 `COACH_DB`，显式 `--db` 优先。 |
| 是否创建演示账号 | `server.py --no-demo`，属于建库/启动选项。 |
| 课程要求、截止日期、教学预算 | 属于活动及其版本化教学数据，保留在活动配置，不用全局文件覆盖。 |
| 本机课题目录 | 从讨论或辅助审阅入口选择。已核验的目录可复用，换目录从 Codex 故障处理选项进入。 |
| 页面同步间隔、文件读取上限 | 目前是实现参数；尚无实际调整需求，本次不扩大配置面。 |

网站运行配置保存模型和时限。教学账号连接凭据由插件单独保存在本机。
