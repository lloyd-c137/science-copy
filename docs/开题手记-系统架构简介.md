# 开题手记怎样工作

在**网站**看任务、核对成果、收到老师意见。在电脑上的 **Codex** 跟 AI 教练讨论、查资料、整理稿件。学生决定自己想研究什么、在网站提交开题稿，老师核对证据、发布正式决定。

## 四个部分各做什么

| 部分 | 你在哪里看到它 | 它做什么 |
| --- | --- | --- |
| **开题手记网站** | 浏览器里的任务页、研究工作区、开题计划与答辩、学习记录、材料和批注 | 保存项目进度、草稿、历次提交、老师意见和已同步的讨论。要确认是否保存或提交，回网站看。 |
| **Codex** | 电脑上打开的聊天窗口 | 学生在这里跟 AI 教练聊，老师可以在这里请 AI 辅助审阅。课题文件夹里的笔记和材料也在本机。 |
| **Research Coach 插件** | 从网站下载并安装，连接后通过网页打开 Codex | 让 Codex 知道这是哪个课题、哪个阶段、谁在使用。它把允许保存的成果和已登记聊天中的可见消息传回网站。 |
| **辅导规则（Skill）** | 插件随包安装，打开 Codex 时自动带入对应规则 | 学生规则告诉 AI 怎样追问、给方向和交回草稿。老师规则告诉 AI 依据哪份稿件审阅、怎样说明证据和保存建议。 |

插件里面负责读写课题的工具叫 **MCP**。聊概念、解释一个例子，通常可以直接回答。你说出新的观察、决定换方向，或已经形成可核对的草稿时，AI 会用这些工具保存。插件还会自动同步已登记的对话原文，所以一轮聊天没有项目工具调用，原话仍可以出现在学习记录里。

网站可以放在学校服务器，文件夹选择和 Codex 仍由师生各自的电脑处理。

## 一份开题稿怎样到老师手上

1. **从网页打开 Codex。** 第一次需要下载安装包、核对教学账号、输入三位码，再选已有课题文件夹。在 Codex 发送网页预填的消息。后续从同一个课题进入时，已核验的文件夹可以复用。
2. **沿着 A–E 逐步准备。** A 从具体观察出发，先比较 2–3 个好懂的方向，试聊后确认想继续的方向。B 把相关问题收拢成核心困惑。C 查来源，形成研究问题和可检验的解释。D 设计方法和最小验证。E 整理一份有版本号的开题计划，并留下学生对这份稿的实际答辩。
3. **先核对，再提交。** AI 可以把讨论整理成草稿。学生可在网站先改一项，确认无误后再完成整阶段。到 F 点「核对并提交老师审阅」，分别展开计划和本稿答辩，最后点「提交老师」。
4. **审阅和补证。** 老师可手工审阅，也可请 Codex 整理建议。以数字人课题为例，老师可要求补单机回放日志，确认控制器是否正确撤回开口动作。自然感还需要体验证据。若正式发布「补证后再判」，学生只重做受影响的阶段，再由本人重交，老师可以对照两次提交。

## 材料在哪里，出现问题找哪里

- **老师要看我电脑里的日志。** 把日志上传到项目的「材料」，并在成果里关联它。放进本机课题文件夹的材料可以在 Codex 里查阅，上传后老师才有对应的网站材料可查。
- **聊天里说保存了，网页还没看到。** 先分清要找的是草稿还是原话。草稿看「当前任务」与「研究工作区」，原话看「学习记录」。断网或关掉 Codex 时，同步可能延后。下次从网站继续并启动插件后，再核对是否补传。
- **Codex 打不开或找不到原目录。** 进入讨论或辅助审阅后，展开「如果打不开 Codex 或原来的讨论」，可更换文件夹、恢复旧讨论或重新连接。[安装与排查](开题手记-插件安装与使用.md)
- **同一台电脑试两个角色。** 先把一个角色的讨论保存并同步，再连另一个教学账号。两个浏览器窗口可以分开登录。若只测老师在网站退回和发布，用「手工审阅」即可。

## 参与测试时怎么报问题

写清楚**哪个站点、哪个账号角色、课题和阶段、页面看到的稿次、做了什么、期待什么、实际发生什么**。评论内容不一致时，附 Codex 中的保存摘要与网页相应一项。这样开发同学能辨认是辅导规则、保存同步还是网页显示的问题。
