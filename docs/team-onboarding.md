# 开题手记项目组上手指南

> [!TIP]
> **不会操作也没关系，直接请 Codex 或 WorkBuddy 帮你做。** 不用先学会写代码、用 Git 或搭网站。告诉它你负责什么、想做到什么，请它查这个仓库，能代做的就直接做。遇到需要你登录、点确认或换一台电脑验证的地方，它会告诉你怎么做。
>
> **开发者**「我第一次接手开题手记。请帮我下载代码、在本机启动演示站，并检查首页能不能打开。」
>
> **部署者**「请按仓库指南，帮我在这台电脑上用局域网 IP 开一个试教站、打包插件，并带我用第二台电脑验证。」
>
> **学生反馈者**「我想用学生账号试一遍开题手记。请带我找到入口。遇到问题后，帮我把操作和现象整理成一条 Issue。」
>
> **老师反馈者**「我想调整 AI 教练在这一步的问法。请帮我找到对应的 Skill，按我的教学意图改一版。我确认后，用我的 GitHub 账号开分支、提交修改并发 PR。」
>
> 第一次用 AI 读这个项目，先看[怎么让 AI 查仓库](#有项目问题先让-ai-查仓库)。

你可以兼任多个角色，按自己这轮要做的事读对应部分。

- [软件开发者](#软件开发者)在自己电脑上运行和修改代码。
- [网站部署者](#网站部署者)把通过检查的版本放到校内试教站，供大家访问。
- [测试反馈者](#测试反馈者)分老师和学生。学生体验开题并反馈，老师体验审阅，也负责编写和更新 Skill。

第一次可以从一台试教电脑、一名学生和一名老师开始，用同一个练习课题走完流程。选一个小问题，实际走一遍反馈、修复、发布和复测。

## 有项目问题，先让 AI 查仓库

用自己的 GitHub 账号打开[开题手记仓库](https://github.com/msh-tutor/proposal-coach)。如果打不开，先请项目组确认你的账号有访问权限。能看到仓库后，选一种方式让 Codex 或 WorkBuddy 读到代码和文档。

- **打开本地文件夹。** 在 GitHub 仓库点 `Code → Download ZIP`，下载后解压。在 Codex 或 WorkBuddy 的桌面应用里打开解压后的项目文件夹，选到能看到 `README.md` 的那一层。已经克隆过仓库的话，直接打开现有文件夹。要查新版时，重新下载或更新本地代码。[GitHub 下载说明](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)
- **在线连接 GitHub。** 如果你的 Codex 或 ChatGPT 里有 GitHub 插件，从「插件」打开 GitHub 并点「连接」。在跳出的 GitHub 页面登录有权限的账号，授权时选中 `msh-tutor/proposal-coach`。如果页面提示需要组织批准，就按提示申请，也可以先用本地文件夹。在聊天里只需发仓库地址和问题。[OpenAI 连接 GitHub 说明](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt)

打开文件夹或连接好 GitHub 后，给 Agent 发一句话试试。

> 请查一下 https://github.com/msh-tutor/proposal-coach 这个项目。先读 README 和相关文档或代码，用简单的话告诉我，学生提交开题计划之后，老师在哪里看到它？请列出你参考的文件。这次只查阅。如果读不到，请告诉我卡在哪一步。

## 软件开发者

### 第一次怎么做

1. 用组织成员账号登录 GitHub，打开本仓库。安装 Git 和 Python 3.12，在终端下载代码。需要推送分支时，请仓库维护者给你写入权限。

   ```sh
   git clone https://github.com/msh-tutor/proposal-coach.git
   cd proposal-coach
   ```

2. 按 [README 的本地启动步骤](../README.md#本地启动)运行网站。打开 `http://127.0.0.1:8767/`，用演示账号登录，确认能进入学生页或老师工作台。
3. 改动涉及 Codex 连接时，再按[运行与打包说明](../proposal_app/README.md#连接-codex)准备本机插件。网页代码在 `proposal_app/static/`，师生辅导规则在 `skills/`。

### 每轮怎么交接

在 Issue（GitHub 的问题单）里认领问题，和反馈者约定改好以后怎么验证。从最新的 `main` 开一个分支，可以用 Codex 或 WorkBuddy 辅助修改。在本机演示库里按原步骤自测。

把分支推到 GitHub，开一个 PR（合并请求）。附上 Issue 链接，写清改动、自测结果，以及部署时是否要更新插件包或处理数据库。请另一位成员检查后合并，再把 PR 和待复测的 Issue 交给网站部署者。

## 网站部署者

### 第一次怎么做

1. 选一台试教期间能保持开机的电脑，下载仓库代码，先按 [README](../README.md#本地启动)在本机跑通。
2. 按[局域网试教搭建指南](lan-https.md)用这台电脑的局域网 IP 开站。部署者自己开启 HTTPS、创建试教账号和打包插件。第一次连接的体验电脑导入一次试教站的根证书。
3. 换另一台电脑连校园网，验证网页登录、插件下载和连接。通过后，在飞书群发试教地址和体验安排，账号信息发给对应的人。

### 每轮怎么交接

收到开发者交来的 PR 后，确认要部署的标签或提交编号。需要变更数据库时先备份，需要更新插件时按试教站地址重新打包。更新后确认网页能登录，插件下载页显示预期版本。

在飞书群公布试教地址、已上线版本、这次改了什么、请谁复测哪些 Issue。把上线版本也记到对应 Issue 里，方便反馈者确认自己测的是哪一版。

如果这轮改了 Skill，先确认本轮发布的提交已提高 [插件版本号](../proposal_app/pilot_install.py)。同一版本号可能继续使用电脑上已有的安装内容。按[运行与打包说明](../proposal_app/README.md#连接-codex)重建试教站提供的 Windows 和 macOS 安装包。更新下载包后，从试教站下载并解压检查，确认新版安装包里有本轮更新的 Skill，再通知老师安装新版并复测。

## 测试反馈者

### 第一次怎么做

1. 向部署者拿试教地址和自己的账号。用自己的电脑登录网站。只参加体验时，直接使用试教站即可。
2. 按[插件安装指南](开题手记-插件安装与使用.md)登录本机 Codex，从试教站下载对应系统的 Research Coach 插件，输入三位连接码，再从网页打开一次讨论或辅助审阅。
3. 和搭档用同一个练习课题。学生按网页顺序完成各阶段，核对开题稿和答辩并送审。老师打开这份提交，发布一次补证意见。学生按意见补证重交，老师再复核。

### 学生怎么反馈

按自己的理解做一遍开题。记下哪一步看不懂、AI 哪句话让你卡住、讨论后网页有没有收到结果。把这些体验写进 Issue，供老师调整辅导规则，或供开发者修正网页和插件。

### 老师怎么更新 Skill

Skill 是写给 AI 的工作说明，告诉它怎么辅导学生或辅助老师审阅。老师负责把教学要求写进仓库，也负责确认改完后 AI 的表现是否符合预期。

1. 第一次接手时，请仓库管理员在 [proposal-coach 的访问设置](https://github.com/msh-tutor/proposal-coach/settings/access)给你的 GitHub 账号添加 **Write** 权限。学生体验和提交 Issue 用 **Read** 就够。
2. 找到要改的入口。学生怎么被引导、AI 什么时候追问，改[学生辅导 Skill](../skills/research-proposal-coach/SKILL.md)。老师如何请 AI 看稿、给出审阅建议，改[老师审阅 Skill](../skills/research-proposal-review/SKILL.md)。具体规则也可能写在各自的 `references/` 里。
3. 拿一段试教中的实际表现作为例子，写清楚 AI 现在怎么做、希望它改成怎么做。可以请 Codex 或 WorkBuddy 帮你改文档，由你确认教学用语和要求。
4. 用自己的 GitHub 账号开分支、提交并推送修改，然后发 PR，请同伴检查后合并。这些操作也可以请 Codex 或 WorkBuddy 用你的账号帮忙完成。
5. 合并后把 PR 和要复测的例子交给部署者。收到新版通知，就从试教站下载并安装，用同一个例子再试一次，把结果和插件版本写回 Issue。

### 每轮怎么交接

遇到卡点，在 [GitHub Issues](https://github.com/msh-tutor/proposal-coach/issues) 新建一条问题单，写上**试教版本、学生或老师身份、操作步骤、期望看到什么、实际看到了什么**。截图先遮住姓名和个人材料。需要讨论时把 Issue 链接发到飞书群，讨论定下的做法和验收条件写回 Issue。

收到部署通知后，优先由原反馈人用新版本按原步骤再做一遍，把结果写回 Issue。问题解决后关闭，仍能复现就补上新版本的现象，交回开发者或部署者继续处理。
